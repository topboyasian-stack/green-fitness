# Responsive and Accessibility Checklist

**Status:** Ready for use; no pass/fail results are implied.

## Viewports and responsive behaviour
- [ ] Check approximately 320px, 375px, 768px and 1280px widths.
- [ ] Confirm no critical horizontal overflow on primary tasks.
- [ ] Confirm mobile touch targets are usable.
- [ ] Ensure sticky/fixed elements do not cover content or focus.
- [ ] Confirm text zoom does not remove functionality.
- [ ] Inspect navigation, cards, forms, buttons, tables and feedback states at each breakpoint.

## Keyboard and focus
- [ ] Complete key journeys with keyboard only.
- [ ] Confirm focus order is understandable.
- [ ] Confirm a visible focus indicator.
- [ ] Confirm buttons/links work with standard keyboard interaction.
- [ ] Confirm there is no keyboard trap.

## Semantics and labels
- [ ] Meaningful page title and logical heading hierarchy.
- [ ] Inputs have visible labels or suitable accessible names.
- [ ] Button/link text describes the action.
- [ ] Informative images have meaningful alternative text.
- [ ] Error messages identify the problem and how to recover.

## Perceivability and content
- [ ] Check text/control contrast with a contrast tool.
- [ ] Status is not communicated by colour alone.
- [ ] Interactive states are clear.
- [ ] Motion does not block access or create unnecessary distraction.
- [ ] Demo/simulated data is clearly disclosed.

## Recording
For each failure, record page/element, steps, expected and actual behaviour, browser/version, dimensions when relevant, evidence and severity/priority rationale. Mark Pass only after the check is performed and recorded.
